# 报价到成交

## 范围与入口

本模块在 Java 业务端实现，不经过模型生成金额或自动批准财务操作。

| 页面 | 地址 | 已实现能力 |
| --- | --- | --- |
| 产品与价格 | `/app/products` | 产品编码、单位、未税标准价、税率、启停；有效期价格表和产品合作单价 |
| 报价单 | `/app/quotes` | 关联商机、服务端计算、独立版本、定稿、客户确认/拒绝、CSV 导出、带版本附件的邮件审批 |
| 合同与回款 | `/app/contracts` | 从确认报价生成合同、条款与服务日期、签署附件、分期计划、回款流水、逾期应收与结清 |

商机详情提供“为此商机创建报价”入口。报价详情在客户确认后可以生成或查看合同。侧栏新增“报价与成交”分组，每页接入详细功能引导。

## 业务规则

### 产品和价格

- 币种当前限定人民币 CNY，产品和价格表单价均为未税价格。
- 产品编码按大写存储，同一工作区唯一；引用后不物理删除，通过停用阻止新报价使用。
- 指定价格表时，该表必须启用且处于有效期，所有报价产品都必须有该表的单价。不静默回退标准价。
- 修改产品或价格表只影响之后保存的报价版本，不回写历史快照。
- 价格表更新与报价保存使用同一价格表行锁，避免替换价格明细时生成混合快照。

### 报价与版本

状态为：`DRAFT → ISSUED → ACCEPTED / REJECTED`，未确认报价也可取消为 `CANCELLED`。

1. 选择进行中的商机、价格来源、产品、数量、折扣、有效期和条款。
2. 点击“计算报价”，读取服务端单价和金额；修改内容后必须重新核算才能保存。
3. 保存创建独立版本。修改现有草稿、定稿或被拒绝的报价时，新增版本并回到草稿，不覆盖旧内容。
4. 主管登记定稿；定稿不代表邮件已经发送，也不代表客户接受。
5. 客户确认或拒绝由有权限的人员登记，并必须填写依据。已确认和已取消报价不能再修订。

每个版本冻结产品名称、编码、单位、单价、税率、折扣、数量、各项金额、买卖方名称、价格表名称、有效期和条款。报价单当前状态与版本号另行维护；查看历史版本时隐藏状态变更入口。

同一产品不能重复添加，单张报价最多 50 项。有效期检查采用 `Asia/Shanghai` 自然日。

金额全部由 Java `BigDecimal` 计算，不能由浏览器提交总额：

```text
行未税金额 = ROUND_HALF_UP(未税单价 × 数量 × (100 - 折扣百分比) / 100, 2)
行税额     = ROUND_HALF_UP(行未税金额 × 税率 / 100, 2)
行含税金额 = 行未税金额 + 行税额
报价总额   = 所有行含税金额之和
```

数量最多 3 位小数，折扣最多 2 位小数且小于 100%，总额必须大于零且不超过 999,999,999,999.99 元。

### 报价附件和邮件

- 导出 UTF-8 BOM 的 CSV，包含单号、版本、销售方、客户、明细、税额、总额和条款，支持中文电子表格读取。
- 对公式前缀和引号做转义，防止产品名称或条款成为电子表格公式。
- “发送报价”仅允许当前有效的定稿版本，使用现有 SMTP 账号配置和高风险 `email.send` 审批执行链。
- 提交时生成该版本的 CSV 附件，保存附件 ID、审批 ID、Agent 运行和操作记录；邮件预览绑定收件人、正文、版本和附件。
- 提交审批不等于发送成功；页面可直接批准或拒绝，并区分审批状态与发送结果。
- 每个版本只允许生成一次邮件审批。待审批、执行中或发送结果未知时，阻止修改和状态变化。需要调整邮件或重新发送时，先核对已有结果，再新建报价版本。
- 实际发送仍由现有工具执行层校验附件存在性并记录邮件，不新增绕过审批的 SMTP 通道。

### 合同与签约

- 只能从客户已确认的报价生成合同，绑定确认的具体版本，金额不可任意修改。
- 每张报价只对应一份合同。已取消草稿仍保留来源关系，避免重复生成；重新洽谈应创建新的报价单。
- 草稿可修改名称、服务期间、条款和完整分期计划；已签约合同不允许覆盖条款或计划。
- 计划为 1 至 24 期，每期金额大于零，各期合计必须精确等于合同含税总额。
- 签约需要客户有效附件：PDF、Word 或图片，支持选择客户已有文件或本地文件。本地选择不会立即上传，点击确认后才上传并登记签约，单文件不超过现有存储限制 10MB。
- 签约日期不能晚于今天或合同结束日。附件必须属于同一工作区、同一客户。
- 签约和关联商机变更为赢单在同一 Java 数据库事务中处理；输单或归档商机不能签约。
- 状态：`DRAFT → SIGNED → COMPLETED`，只有草稿可取消为 `CANCELLED`。

### 回款与幂等

- 只有已签约且未结清合同可以收款。每次登记指定一期计划、到账日期、金额、银行/支付流水号和备注。
- 金额精确到分且大于零，不能超过本期剩余应收，到账日期不能是未来日期。
- 同一合同流水号唯一；请求使用 UUID 幂等键，同一请求重试返回既有结果，不重复登记。
- 完全相同的重试允许携带原来的旧版本号，以处理“服务端成功但网络响应丢失”；同一键更换金额、合同、款项或其他内容会拒绝。
- 先锁合同父行，再查询本期已收金额并写流水，同时递增合同版本，防止并发超收和覆盖。
- 已收金额由独立流水汇总，不允许客户端直接覆盖余额。全部结清后自动变更为 `COMPLETED`。
- 应收页面只列已签约合同的未结清分期；草稿和取消合同不计算应收。逾期按上海时区自然日判断，已付清分期不显示为逾期。

## 权限与数据隔离

| 操作 | OWNER / ADMIN / MANAGER | SALES | VIEWER | 游客 |
| --- | --- | --- | --- | --- |
| 产品与价格表读取 | 团队内 | 团队内 | 团队内 | 模拟数据 |
| 维护产品与价格 | 可以 | 不可以 | 不可以 | 不可以 |
| 报价/合同读取 | 团队内 | 当前分配商机 | 当前分配商机 | 模拟数据 |
| 创建/修订报价、合同草稿 | 可以 | 当前分配商机 | 不可以 | 不可以 |
| 报价定稿、确认、拒绝、取消 | 可以 | 不可以 | 不可以 | 不可以 |
| 提交报价邮件审批 | 可以 | 当前分配商机 | 不可以 | 不可以 |
| 签约、取消合同、登记回款 | 可以 | 不可以 | 不可以 | 不可以 |

审批处理继续遵守系统既有邮件审批权限。所有商业单据查询使用登录主体的工作区；销售的单据范围进一步限制为商机当前负责人。子表通过带工作区的复合外键约束，避免跨租户关联。

游客请求在现有 Axios 拦截层返回模拟产品、报价版本、合同和回款，不请求正式商业数据；写操作在发出前拒绝。正式用户接口错误不回退模拟成功。

## 数据与接口

迁移：`db/migration/V19__quote_to_cash.sql`，由现有 Flyway 启动迁移加载。

新增表：`sales_product`、`sales_price_book`、`sales_price_entry`、`sales_quote`、`sales_quote_version`、`sales_quote_line`、`sales_contract`、`sales_payment_plan`、`sales_receipt`、`sales_commercial_event`。

Java 代码位于 `commercial/api`、`commercial/application`、`commercial/infrastructure`，MyBatis SQL 位于 `mapper/commercial/CommercialMapper.xml`。Python AI 服务不需要改动，不增加新依赖。

接口统一前缀 `/api/v1/commercial`：

| 资源 | 主要接口 |
| --- | --- |
| 产品 | `GET/POST /products`、`PUT /products/{id}` |
| 价格表 | `GET/POST /price-books`、`GET/PUT /price-books/{id}` |
| 报价 | `GET/POST /quotes`、`GET /quotes/{id}?revision=N`、`POST /quotes/preview` |
| 版本与状态 | `POST /quotes/{id}/versions`、`POST /quotes/{id}/decisions/{issue\|accept\|reject\|cancel}` |
| 附件与发送 | `GET /quotes/{id}/versions/{revision}/export`、`POST /quotes/{id}/send` |
| 合同 | `GET/POST /contracts`、`GET/PUT /contracts/{id}`、`POST /contracts/{id}/sign`、`POST /contracts/{id}/cancel` |
| 签署附件 | `GET /contracts/{id}/signed-file`，经过合同权限校验 |
| 回款 | `POST /contracts/{id}/installments/{plan}/receipts` |
| 应收与汇总 | `GET /receivables?overdue=true`、`GET /metrics` |

列表分页最大 100 条，默认 20 条。单据更新携带 `version`，冲突返回现有统一 409 提示，刷新核对后重试。

## 部署与验收

1. 备份正式数据库，先在测试环境部署；Java 启动应用 V19，确认迁移成功后发布匹配前端。
2. 管理员创建产品与价格表；销售使用已有客户和商机创建报价，核对未税、税额、含税总额。
3. 调整价格后创建新版本，核对旧版本仍不变，并导出 CSV 检查中文、金额和条款。
4. 配置当前系统 SMTP，提交报价审批，核对收件人、正文、版本与附件，再批准。核对邮件记录而不只看“审批已批准”。
5. 登记客户确认，生成合同，尝试不匹配的分期金额应被阻止。
6. 确认本地选文件尚未上传；提交签约后检查签署附件与商机赢单状态。
7. 分次登记回款，检查部分回款、逾期、付清和合同结清；重复流水、超额、未来到账日、跨工作区访问均应拒绝。

## 当前边界

- 报价导出为 CSV，不伪称已提供 PDF/Word 模板排版。
- 合同目前是业务登记和签署文件归档，不是电子签章平台，也不会自动生成有法律效力的签名。
- 回款为人工登记，不接银行自动对账，不代替财务凭证或发票。
- 暂不包括多币种、续约/变更合同、退款冲销、坏账核销或回款自动提醒；不可通过修改已签合同或删除流水代替这些未来流程。
- 本次不新增 MCP 财务写入工具，不允许模型直接定稿报价、签约或登记资金。
