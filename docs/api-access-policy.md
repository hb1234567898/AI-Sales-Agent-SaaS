# API 登录访问策略

业务 API 默认需要有效 Access Token。没有令牌、令牌无效或已失效的业务请求返回 `401`，不进入业务处理器；已登录但不具备接口要求的角色时返回 `403`。

## 按前缀选择访问规则

| 前缀 | 认证规则 |
| --- | --- |
| `/api/public/**` | 免 Access Token，适用于登录、公钥、基础健康检查等公开接口 |
| `/api/v1/**` | 必须登录，适用于业务数据和受保护操作 |
| 其他路径 | 默认要求登录，避免未分类的新接口意外公开 |

新增接口直接选择前缀，不需要逐条修改 Spring Security 白名单。管理员权限、组织和成员可见范围继续由业务层校验。

## 当前公开接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| POST | `/api/public/auth/login` | 验证账号密码并签发令牌 |
| POST | `/api/public/auth/refresh` | 验证 Refresh Token 并轮换令牌 |
| GET | `/api/public/auth/password-key` | 获取登录密码传输公钥 |
| GET | `/api/public/health` | 基础存活检查，不返回详细信息 |

前缀决定是否要求 Access Token，控制器限定请求方法。公开登录入口仍会校验账号密码，刷新入口仍会校验 Refresh Token。跨域预检由 CORS 处理，不返回业务数据。

## 登录后可请求的业务接口

- 客户档案、客户统计、负责人及互动记录、聊天分析结果。
- 线索、商机、跟进任务、提醒与自动跟进规则。
- 客户附件、模型配置状态、邮箱配置和客户邮件。
- 产品价格、报价、合同、签约文件与回款。
- 企业知识库、资料下载、MCP 会话、审批及 Agent 运行记录。
- 当前登录会话、退出登录、系统业务健康接口。Actuator 只暴露 `/api/public/health`，不暴露 info。
- 成员、团队及审计接口：除登录外，继续保留管理员/所有者的角色限制。
- 客户删除：继续保留管理员/所有者权限、版本和报价关联校验。

全局安全规则也覆盖未来新增接口，新增业务 GET 不会自动向匿名请求开放。游客体验使用前端模拟数据，不依赖匿名读取真实业务 API。

## 验证与部署

`ApiAuthenticationBoundaryTests` 使用生产安全过滤链，覆盖匿名和无效令牌请求被拒绝、正常 Bearer 和备用请求头认证、公开前缀、真实登录/刷新/公钥控制器、跨域预检及客户删除角色限制。`PublicHealthEndpointTests` 验证实际 Actuator 路径及健康详情不对外返回。

本次修改解决匿名访问入口。登录后的组织隔离、成员可见范围及各类写操作的角色权限仍需按业务服务逐项检查，不能由“已登录”替代。

必须发布并重启后端后，新规则才会在线上生效；仅更新前端无法修复匿名访问问题。

## 路径迁移

登录、刷新和公钥从 `/api/v1/auth/` 迁到 `/api/public/auth/`；`session`、`logout` 继续保留在 `/api/v1/auth/`。原 `/actuator/health` 改为 `/api/public/health`，通过现有 Nginx `/api/` 代理。

前后端需一同发布，旧版桌面客户端也需更新。旧登录路径不再匿名放行；部署监控探针需使用新健康检查地址。
