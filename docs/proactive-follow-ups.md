# 主动跟进

## 功能范围

- 跟进任务：新建、编辑、完成、取消、延期，保留已结束记录；更新时使用版本号防止覆盖他人的修改。
- 工作台：展示当前用户的实时待办，可以直接完成任务或打开任务详情。
- 主动跟进：按客户计划时间或连续未联系天数生成待办，可选调用现有 Agent 生成建议。
- 站内通知：临近到期、逾期提醒，支持逐条和全部已读，点击直达任务详情。
- 游客模式：完全使用模拟任务、规则和提醒，所有写操作禁用。

本期不包含短信、微信、浏览器系统推送或无人审批自动发邮件。

## 如何使用

1. 进入「跟进任务」，新建客户沟通任务，选择客户、负责人、时间、方式及优先级。
2. 点击「自动跟进」，开启个人规则。首次默认关闭，不会自动调用模型。
3. 配置未联系天数、每日北京时间、每日最多客户数，以及提醒提前分钟数，保存规则。
4. 需要 AI 建议时再开启「同时生成 AI 跟进建议」。它使用当前规则所属成员的模型配置和个人 Token 额度。
5. 可以点击「立即检查」验证规则。同一北京时间日期只检查一次，不会因为重复点击重复创建任务。
6. 在右上角通知、工作台或跟进任务页处理待办。AI 建议也会记录到 Agent 运行；对外邮件等操作仍需经过现有审批。

默认值：7 天未联系、北京时间 09:00、每天最多 5 位客户、提前 30 分钟提醒、AI 分析关闭。

## 自动检查规则

只处理规则所属成员负责的、未删除且处于 ACTIVE 状态的客户，不处理已赢单或丢单客户。满足任一条件进入候选：

- 客户计划跟进时间已经到达；
- 最后互动时间距今超过配置天数，没有互动时使用客户创建时间。

已有未结束任务，或最近配置天数内已创建/完成过跟进任务的客户会被跳过。候选优先按计划时间、评分排序；评分及下一步动作从客户的 JSON 扩展字段读取。生成的待办来源为「自动跟进」，计划时间为检查时间后一小时。

客户范围是个人规则的范围，不会因为管理员角色而自动扫描团队其他成员的客户。

## 调用关系与可靠性

定时扫描由 Java 负责，默认启动后 10 秒开始，每 60 秒扫描一次：

1. 生成临近到期/逾期提醒，并将中断超过两小时的 AI 批次标记为失败。
2. 查找当天已到配置时间、还未执行的个人规则。
3. 短事务锁定规则，创建日批次和待办；数据库唯一约束防止多实例或重复请求重复生成。
4. 若开启 AI 且确实创建了任务，将批次持久化为 QUEUED；否则直接完成。
5. 有界线程池每次提取少量批次，通过状态条件更新领取任务，防止重复执行。
6. 执行前重新检查规则、成员状态及客户归属。关闭规则、成员停用或客户不再符合条件时不会继续分析。
7. 复用 SalesFollowUpAgentService，以 SCHEDULED 触发类型记录运行，并通过现有 AI 编排客户端调用 Python AI 服务。
8. 分析结果生成审批建议。批次保存 Agent 运行 ID 与最终状态，页面可查看失败提示。

AI 分析只使用现有 Agent 能读取到的最近 180 天客户互动。没有可分析互动时仍保留普通待办，不会凭空生成客户分析。

失败批次不会当天自动重跑，避免重复消耗 Token 或重复创建审批。运行中进程重启留下的批次在两小时后标记失败，需先核对 Agent 记录。排队批次保存在数据库，应用重启后会继续领取。关闭规则不会删除已生成待办，只会阻止后续自动检查和尚未开始的 AI 分析。

## 提醒与权限

提醒按组织、任务、负责人、提醒类型、计划时间去重。临近到期和逾期各最多一条；到期前提醒已读后，任务真正逾期仍可出现新的逾期提醒。延期、转派、完成、取消或客户停用后，旧提醒不再显示。

前端每 30 秒刷新任务和提醒；打开规则弹窗后每 5 秒刷新运行状态。未结束任务和统计在数据库按完整范围计算，不是当前分页数量。

- OWNER / ADMIN / MANAGER：可查看团队任务并分配负责人。
- SALES：只能操作自己的或未分配的任务，新建/编辑只能分配给自己；客户也必须是自己的或未分配客户。
- VIEWER：只读。
- 所有新增接口均要求登录，使用登录身份的 organizationId / memberId，不信任客户端传入租户。
- 今日到期与日批次统一按 Asia/Shanghai 划分；时间传输和数据库仍使用带时区时间，不手工加减八小时。

## 部署

随 Java 后端部署 `db/migration/V17__proactive_follow_ups.sql`，通过现有 Flyway 流程执行。新增规则、日批次及提醒表，并为任务增加 RULE 来源和自动批次关联。

无需新增 Python 接口、Python 依赖、SMTP 参数或运行时 Java 依赖。可通过 Java 配置调整扫描参数：

```properties
app.follow-up.scheduler-enabled=true
app.follow-up.scan-interval-ms=60000
app.follow-up.initial-delay-ms=10000
```

关闭 scheduler 只停止后台扫描，不会关闭任务 CRUD，也不会关闭登录用户读取站内提醒时的按需生成。

## 验证

后端覆盖租户/角色权限、版本冲突、未来延期校验、上海日期边界、默认关闭 AI、日批次去重、并发领取、关闭规则取消队列、Agent 租户传递。

PostgreSQL 集成测试在隔离临时 schema 中执行迁移和实际 Mapper SQL，并在结束时回滚：

```powershell
$env:FOLLOW_UP_TEST_DB_URL='jdbc:postgresql://127.0.0.1:55433/postgres'
$env:FOLLOW_UP_TEST_DB_USER='opportunity_test'
$env:FOLLOW_UP_TEST_DB_PASSWORD=''
cd backend
.\mvnw.cmd -o -Dtest=FollowUpPostgresTests test
```

前端覆盖新建、编辑冲突、完成/延期、分页、规则保存约束、提醒直达、已读、游客只读，并检查桌面和手机布局。
