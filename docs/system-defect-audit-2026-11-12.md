# 系统缺陷检查：2026-11-12

本轮检查客户、线索、互动分析与 MCP 助手的实际调用链。公开与登录接口仍沿用已有前缀规则。

## 已修复

| 缺陷 | 原因与修复 |
| --- | --- |
| 不同组织的客户、联系人与互动数据可能混用 | CustomerService、InteractionService、ChatAnalysisService 的用户入口原先使用固定演示组织。现在显式传入登录身份，查询和写入使用身份所属组织；删除固定组织的用户入口。 |
| MCP 助手查客户、建客户、导入聊天及查审批未完整使用当前组织 | 向工具调用链传递登录身份，包括待审批列表及运行结果摘要，复用同一套业务权限检查。 |
| 只读成员可通过业务 API 或助手修改 CRM | 新增服务层写权限校验，限制客户新增/编辑、线索新增/导入/分配/转化、互动记录、聊天导入、AI 分析及应用结果；只读和未知角色在访问数据库或模型前被拒绝。线索页面按钮同步禁用。 |
| 名称模糊时助手可能创建重复客户 | 原先把多个相似客户引发的异常当作未找到客户。现在只有查询结果为空且指令明确允许创建时才创建，多个结果要求澄清。 |
| 历史互动正文为空时，AI 分析会出现空指针异常 | 对空正文返回可理解的校验错误，阻止模型调用。 |
| 线索保存失败产生未处理的 Promise 拒绝 | 提交函数捕获失败，保留表单和父级错误提示；只读或正在保存时不重复提交。 |

## 已核对的功能关系

线索直接存储在 customer 表，转化时保留同一 ID，因此线索跟进记录复用客户互动接口是正确设计。保留该入口，不创建重复档案。

## 验证

- 后端全量 202 项用例：197 项通过，5 项按环境条件跳过，无失败。包括组织查询条件、跨组织资源拒绝、只读权限、助手模糊匹配、真实安全过滤链及应用启动测试。
- 前端线索页面覆盖正常分配、新建、只读按钮权限、保存失败后的表单保留。类型检查、Lint 和生产构建通过。
- 测试中的组织隔离通过实际业务服务和查询参数验证；未执行双组织真实数据库端到端联调。

## 待继续验证

- 客户更新请求没有携带页面读取时的版本号。需补充双会话并发保存验证，确认旧表单能否覆盖其他成员的新修改。
- 模型、邮箱等组织配置的写权限仍需结合产品角色要求逐项核对；本轮写权限修复覆盖客户、线索、互动及其助手调用链，不能视为整个系统的权限审计结论。
