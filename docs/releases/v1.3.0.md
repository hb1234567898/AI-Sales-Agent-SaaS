# 1.3.0 发布说明

本次包含兼容的新功能，按语义化版本从 1.2.2 升级到 1.3.0。
计划桌面标签：`desktop-v1.3.0`。此文档不表示正式版已经发布。

## 新增与改进

- 主动跟进：成员级规则、自动生成去重任务、到期提醒、延期与完成操作。
- 工作台：显示真实跟进任务，右上角通知可直接查看待办。
- 客户邮件：在线配置团队 IMAP 邮箱、增量同步、关联客户和互动记录。
- 邮件回复闭环：来信生成跟进任务，回复经过审批后发送，支持已上传附件。
- 发送保护：阻止并发重复执行，发送结果不确定时禁止自动重试。
- 桌面图标：使用蓝色背景、白色标志，保留透明圆角和多分辨率 ICO。

## 部署注意

1. 备份 PostgreSQL，再通过现有 Flyway 流程执行 V17、V18 迁移。
2. 部署包含本次后端的完整发布包，再更新网页与桌面客户端。
3. 主动跟进规则和邮箱同步默认关闭；在成员规则和邮箱设置中按需开启。
4. 配置真实 IMAP/SMTP 邮箱后，验收收信、客户关联、审批、附件回复与发送记录。
5. 遇到 UNKNOWN 发送状态，先到原邮箱核对，不要重复发送。

本次不新增运行时依赖，不改变现有 Java 业务后端与 Python AI 服务的职责。
详细说明见 [主动跟进](../proactive-follow-ups.md) 和 [邮件闭环](../email-reply-loop.md)。

## 正式发布清单

- PR 合并至 develop 前完成 CI 和至少一名非作者评审。
- 经过 staging 验收后，从 develop 创建 release 分支并通过 PR 合并至 main。
- 在 main 对应提交创建 `desktop-v1.3.0` 标签，触发桌面发布流水线。
- 确认 GitHub Release 含安装包、签名及版本为 1.3.0 的 latest.json。
- 已安装应用通过原有后台下载、手动安装或下次重启安装流程更新。

## 回滚

保留部署前发布包和数据库备份。应用可切回上一版本，新增表和邮件记录应先保留，
不要直接删除迁移后的业务数据。已有来信和 SMTP 发送记录必须核对后再处理。
桌面端不能依靠发布更低版本触发自动降级，需发布修复版本或手动安装旧包。
